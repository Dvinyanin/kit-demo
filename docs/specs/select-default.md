Статус: от 2026-10-15; сверка выполнена, расхождения исправлены (§8, §9). Micro описан как отличия от Default (§4). Замечания к макету для дизайнера в §7. Дополнено 2026-10-15: подпись (§12), Required (§13), Read Only не открывает список, значение без лейбла по центру, ширина по родителю (§4, §5).

## 3. Токены (состояние × элемент)

Выписано из `get_design_context` вариантов. Micro использует те же токены, что и Default, отдельной таблицы для него нет.

| ----------- | ---------------------- | ---------------------- | --------------------- | --------------------- | ------------------------- | ------------------------- |
| Фон         | `--bg-surface`         | `--bg-surface`         | `--bg-surface`        | `--bg-surface`        | `--bg-surface-disabled`   | `--bg-surface-disabled`   |
| Бордер      | `--border`             | `--border-accent`      | `--border-danger`     | `--border-danger` ¹   | `--border-alt`            | `--border-alt`            |
| Лейбл       | `--texticon-secondary` | `--texticon-accent`    | `--texticon-danger`   | `--texticon-danger`   | `--texticon-disabled` ²   | `--texticon-secondary`    |
| Значение    | `--texticon`           | `--texticon`           | `--texticon`          | `--texticon`          | `--texticon-disabled`     | `--texticon`              |
| Плейсхолдер | `--texticon-tertiary`  | `--texticon-tertiary`  | `--texticon-tertiary` | `--texticon-tertiary` | `--texticon-tertiary`     | `--texticon-tertiary`     |
| Подпись     | `--texticon-secondary` | `--texticon-secondary` | `--texticon-danger`   | `--texticon-danger`   | `--texticon-secondary`    | `--texticon-secondary`    |
| Шеврон ³    | `--texticon-tertiary`  | `--texticon-active`    | `--texticon-tertiary` | `--texticon-active`   | `--texticon-disabled-alt` | `--texticon-disabled-alt` |

Как получены шевроны (цвет лежит в SVG, а не в переменной): Default и Error `#4E6180` при `fill-opacity 0.6` = `--neutral-80-adapt` = `--texticon-tertiary`; Focus `#222A37` = `--neutral-900` = `--texticon-active`; Disabled и Read Only `#95A0B3` при `0.5` = `--neutral-80-a50` = `--texticon-disabled-alt`.

Плейсхолдер проверен по ячейкам Showcase в Default, Disabled и Read Only; для остальных состояний значение взято по указанию («плейсхолдер всегда `--texticon-tertiary`»).

¹ Состояние описано только текстом в Showcase («Error + Focus»), ячейки в макете нет. Красный лейбл и красный бордер (`--border-danger`, как у Error) выбраны по аналогии: у Focus бордер `--border-accent`, а не `--border-accent-active`. Не из макета: состояние в нём не показано. Шеврон в этом состоянии как в Focus (`--texticon-active`), решено 2026-10-15.
² В Micro-варианте Disabled макет показывает лейбл `--texticon-secondary`. Решено считать это ошибкой макета: для обоих размеров `--texticon-disabled` (§7).
³ Для Disabled и Read Only совпадает `fill-opacity`, для Focus шеврон непрозрачный.

## 5. Поведение

- Лейбл всплывает вверх и уменьшается, если есть значение или плейсхолдер, либо открыт попап. Без значения и в покое лейбл крупный и по центру.
- В открытом состоянии шеврон повёрнут вверх.
- Read Only: не открывает список ни мышью, ни клавиатурой, значение не меняется, но поле остаётся читаемым и доступным по Tab; цвета текста не «выцветшие», как в Disabled. Решение 2026-10-15: Base UI в `readOnly` позволяет открыть список для просмотра, поэтому открытие отменяется в `onOpenChange`.
- Без лейбла (Only Input, Only Placeholder) значение или плейсхолдер стоит по центру высоты поля, как в макете; вверх прижимается только стек «лейбл + значение».
- Hover у триггера в макете нет.
- Анимация переходов (50 ms `ease-in-out`) и появления меню (150 ms `cubic-bezier(0.7, 0, 0.84, 0)`) в макете задана, в код не переносится.

- Clear появляется, когда есть значение. Нажатие сбрасывает значение (`undefined` в `Select`, `[]` в `MultiSelect`; в `SelectCore` `null` и `[]`) и не открывает попап.

- Кликабельная Trailing-иконка тоже не открывает попап.
- Размер иконок в Micro такой же, 20×20 (по `Select Micro – Guides`).
- В Guides сказано, что у Clear есть градиент для плавного скрытия текста под иконкой. Не делается (решение 2026-10-15).
- Очистка нужна и в Micro (решение 2026-10-15), хотя в примере «Single or Multi» для Micro её нет.

Для дизайнера:

- Цвет Leading и Trailing не меняется в Disabled и Read Only. Решено 2026-10-15: пока оставляем как в макете (`--texticon-tertiary`), вопрос уточняется.

| Suffix: зазор до бокса шеврона Default (Micro)      | 12 (10)                                                                                      | 12 (10)                                                           |
| Очистка одиночного                                  | значение → плейсхолдер, попап не открывается                                                 | выполняется                                                       |
| Нажатие Trailing-иконки                             | не открывает попап                                                                           | не открывает                                                      |
| Клавиатура                                          | Tab: триггер, очистка; Enter на очистке сбрасывает без открытия; Enter на триггере открывает | выполняется                                                       |

Как устроено: иконка слота задаётся именем (`iconRight="help-circle-filled"`) или компонентом `Select.Icon` (`MultiSelect.Icon`): `<Select.Icon type="help-circle-filled" onClick={…} label="Подсказка" />`. С `onClick` это кнопка (`label` — её доступное имя), которая не открывает список; без него обычная иконка. То же работает для `iconLeft`. Так как внутри триггера бывают кнопки (очистка, `Select.Icon` с `onClick`), а в `<button>` они недопустимы, триггер всегда `div` с `role="combobox"` (`nativeButton={false}`). Кнопка очистки есть в DOM всегда при `clearable`, а скрывается CSS (`display: none`), когда у значения стоит `data-placeholder`, в Disabled и в Read Only. Нажатие вызывает `onValueChange` с `null` (в `MultiSelect` `[]`); `Select` и `MultiSelect` переводят `null` в `undefined`.

## 12. Подпись (Caption)

Источник: Showcase, секция `3809:51461` («Любое поле может иметь описание. Поля с ошибкой либо имеют такой же текст ошибки, что и подпись, либо заменяет обычную её»). Библиотека: `.⚙️ Caption` (`5494:20399`) со свойствами `error`, `withPadding`, `showButtonOptional`.

| Параметр            | Default                      | Micro       | Код                                                   |
| ------------------- | ---------------------------- | ----------- | ----------------------------------------------------- |
| Шрифт               | 12/16, ls 0.2 (`body-small`) | как Default | `.captionText`, `.errorText` (`composes: body-small`) |
| Цвет подписи        | `--texticon-secondary`       | как Default |                                                       |
| Цвет подписи ошибки | `--texticon-danger`          | как Default |                                                       |
| Отступ сверху       | 4                            | как Default | `gap` обёртки                                         |
| Отступ слева        | 12                           | **10**      | `padding-left` у `& + .captionText`                   |

Поведение: подпись выводит проп `caption`; `error` (текст или узел) заменяет `caption` (подпись ошибки) и по умолчанию включает `invalid`; чтобы окрасить поле без текста, задаётся `invalid`. Пустое значение проверяет `isReactNodeNotEmpty` (`true` и `false` не считаются непустыми). Disabled и Read Only показывают обычную подпись (в макете этих ячеек нет). Не делается: необязательная кнопка «More» после текста ошибки (`showButtonOptional`; текст должен быть Hug, кнопка сразу после него).

Кадр: `Components/Selects/Select/States` → `Caption` (сверено с макетом по токенам и скриншоту, 2026-10-15).

## 13. Required

Источник: Showcase, секция `3809:51487` («Поля, имеющие лейбл или плейсхолдер могут использовать индикатор»); индикатор — компонент `.⚙️ status-dot-required` (`3725:76620`).

| Параметр   | Значение                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| Вид        | точка `--texticon-warning`, радиус 4; Default 5×5, Micro 4×4 (после плейсхолдера в Micro 5×5, §7, п. 7) |
| Положение  | сразу после текста лейбла, отступ 4px, верх по верху строки текста, смещение 2px вниз                   |
| Без лейбла | после плейсхолдера; значение без лейбла индикатор не показывает (в макете такой ячейки нет)             |
| Проп       | `required` (также передаётся в Base UI: `aria-required` и проверка формы)                               |

Как устроено: точка рисуется в CSS псевдоэлементом `::after` у лейбла (без лейбла у плейсхолдера) при `aria-required="true"` на триггере; Base UI ставит этот атрибут сам, отдельного класса и разметки нет. Заменил прежнюю красную звёздочку (`--texticon-danger`, `*`), которой в макете нет. Кадр: `Components/Selects/Select/States` → `Required` (четыре сочетания содержимого × Default/Micro).
