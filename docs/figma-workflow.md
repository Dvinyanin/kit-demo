# Figma → код → Storybook: процесс работы

Документ описывает, как передавать Claude макеты из Figma, по какому процессу разрабатывается компонент и какие правки в Figma упростят работу. Короткая выжимка правил лежит в [CLAUDE.md](../CLAUDE.md).

---

## 1. Как устроены файлы Figma

Селекта как одного компонента в макетах нет. Триггер — это поле ввода (Input) с шевроном, попап — отдельный компонент Dropdown, а размеры, анимация и описание поведения лежат в третьем месте. Источники разнесены по двум файлам и нескольким страницам.

### Components — библиотека (`webComponents`, `BWW9MBiu5dHwUb8ENACEmi`)

Страница = семейство компонентов. Хранит **из чего компонент сделан и какими переменными (токенами)**.

| Страница                | node        | Что на ней                                                                                                                                                                                                                                                      |
| ----------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fields (Input & Select) | `443:465`   | Секции `Field [Default]` и `Field [Micro]`: Text / Number / Date / Time Input, Select, Select Multiple, Select Country. Это одна база «поле» (`Wrapper`: Leading, Input Wrapper, Trailing, Suffix, Chevron Icon). Триггер селекта = Input + Chevron Icon.       |
| Dropdown (Select & Tag) | `1022:3042` | `❖ Dropdown` и `❖ Dropdown Micro`: Simple, Advanced (Single, Multi, Text Input), Nested. Рядом `⚙️ Assets` (Cell, List, Search, Tabs, Footer, Value Cell, Group Header) и `sandbox`. Advanced с Text Input — это то, что в коде называется ComboBox (гипотеза). |

Устройство: наборы вариантов. Например, `Select [Default]` (`8696:12557`) — пять вариантов `State=Default / Focus / Error / Disabled / Read Only`; Micro — отдельный набор. Эмодзи-префиксы в именах (`🎹 State`, `🎛️ Mode`, `📦 Content`, `🎲 Selected`, `💠 Type`, `⚙️` для внутренних деталей) по виду обозначают вид свойства или служебную деталь; это догадка, стоит подтвердить у дизайнера.

### Showcase — витрина-документация (`showcase`, `GmAU0pPfs0WxcKNJyApuD0`)

Страница = компонент (`Select Default + Micro` — `324:4691`, `Select Dropdown` — `674:23206`). Состоит из экземпляров библиотечных компонентов и подписей. Хранит **как компонент должен себя вести: какие бывают состояния и сочетания содержимого, какие отступы и анимации**.

| Блок на странице   | Что в нём                                                                                                                                                                                                                                |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `… – Specificaton` | Сетки состояний Light / Dark × Default / Micro и текстовые описания. Секции разбиты по сочетаниям содержимого: Only Label, Label + Input, Only Input, Label + Placeholder, Only Placeholder, Additional, Icon State.                     |
| `… – Guides`       | `Paddings Inside`, `Gap Outside`, `Animation`, `Parent paddings`: геометрия и анимация, которых нет в данных компонента. Например, переход состояний поля — 50 ms `ease-in-out`, открытие меню — 150 ms `cubic-bezier(0.7, 0, 0.84, 0)`. |
| `Изменения`        | Журнал со скриншотами за июнь 2025. Для разработки не нужен.                                                                                                                                                                             |

### Вывод

Одного места, где описано всё, нет. Библиотека отвечает на «из чего и какими токенами», витрина — на «как себя ведёт, какие бывают сочетания и отступы». Для `Select` источников четыре:

| Что нужно                                                  | Где брать                                                                                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Токены триггера по состояниям                              | Components → Fields → набор `Select [Default]` / `Select [Micro]` (варианты `State`).                                                |
| Какие состояния и сочетания содержимого существуют, тексты | Showcase → Select Default + Micro → `Select [Default + Micro] – Specificaton`.                                                       |
| Отступы, gap, анимация                                     | Showcase → Select Default + Micro → `Select Default – Guides` и `Select Micro – Guides`.                                             |
| Попап                                                      | Components → Dropdown (Select & Tag) → `Dropdown [Simple]` и Showcase → Select Dropdown → `Dropdown Simple (Single) – Specificaton`. |

В спеке каждого компонента этот список источников записывается первым разделом.

`core` (`yu7J1b0um9Q8th1VQWUWBP`) содержит базовые стили; для Select не понадобился.

Про идентификаторы: в описаниях компонентов, которые приходят вместе с узлами витрины, `Select [Default]` значится как `5497:107484`, а при запросе библиотеки тот же компонент (то же описание) — `8696:12557`. К библиотеке нужно обращаться по её собственным id (`8696:…`); `5497:…` там не находится.

## 2. Как давать ссылки

### Правила

1. **Ссылка всегда с `node-id`.** В Figma: выделить слой → ПКМ → _Copy link to selection_. Без `node-id` Claude видит только список страниц. `&m=dev` в ссылке не мешает.
2. **Уровень ссылки определяет, что получится:**

   | Уровень                                                | Пример                                   | Для чего                                                                                                                    |
   | ------------------------------------------------------ | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
   | Вся страница компонента (`… Specification`, 2000×8912) | `3809-50902`                             | Только оглавление: список секций и их node-id. Дизайн-контекст целиком не влезает (≈87 000 символов на одну секцию States). |
   | **Секция** (`_Section`: описание + сетка Light/Dark)   | `3809-51228` (States – Label + Input)    | **Основная единица работы.** Из неё строится карта «ячейка → состояние», дальше по каждой ячейке снимаются токены.          |
   | Одна ячейка (экземпляр компонента в сетке)             | `3810-27365` (Read Only, Default, Light) | Точечная проверка спорного места. Даёт точные токены по каждому элементу: фон, бордер, лейбл, значение, иконка.             |

3. **Скриншот не заменяет ссылку.** По картинке нельзя отличить `--texticon-disabled` от `--texticon-disabled-alt` (та же базовая краска, но 50% прозрачности). Ровно на этом спотыкались при работе над Select.
4. **Ссылки на источники необязательны, если компонент описан в §1.** Тогда Claude берёт страницы из таблицы источников сам. Ссылки нужны для нового компонента и для спорных мест. Формат:

   ```
   Компонент: Select
   Showcase:   <… Specificaton>   ← оглавление; секции: <States – Label + Input>, <States – Only Label>
   Components: <Select [Default]>  ← варианты и токены
   Guides:     <Select Default – Guides>
   Фокус:      Read Only, Disabled ← если важно что-то конкретное
   ```

5. Ссылка на библиотеку и ссылка на витрину отвечают на разные вопросы (см. §1), поэтому в сообщении стоит писать, что за ссылка: «варианты и токены» или «поведение и отступы».

### Что Claude делает со ссылкой на секцию

1. `get_metadata` по секции даёт экземпляры и стикеры состояний с координатами.
2. Сопоставление «экземпляр → состояние» идёт по данным, а не по координатам стикера. В `data-node-id` из `get_design_context` вложенные узлы записаны как `I<ячейка>;<id узла в библиотеке>`. Таблица «узел библиотеки → вариант» строится один раз по `get_metadata` набора вариантов (`8696:12557`). Пример: `I3810:27365;8696:12583` — обёртка варианта `8696:12582` = `State=Read Only`. Проверено на Focus, Disabled и Read Only: id обёртки на единицу больше id варианта.
3. `get_design_context` по каждой ячейке (≈3–5 тыс. токенов на ячейку) даёт таблицу «элемент → токен».
4. **Вариант из библиотеки** (`get_design_context` по `8696:12582` и аналогам) отдаёт те же токены, что и ячейка витрины (проверено на Read Only: фон, бордер, лейбл и значение совпали), и ещё **свойства компонента**: `state`, `showCaption`, `showLeading`, `showTrailing`, `showSuffix`. Это ближайшее к «компоненту, где всё описано»: он годится для снятия токенов и API, а витрина нужна для состава сочетаний, поведения, отступов и анимации.
5. **Иконки приходят SVG-картинкой с hex**, а не переменной. Hex с учётом `fill-opacity` переводится обратно в токен через `src/theme/*.css` (пример: `#95A0B3` при `0.5` = `--texticon-disabled-alt`, а при `1` = `--texticon-disabled`). Если один hex соответствует нескольким семантическим токенам, в спеке ставится `?` и вопрос.
6. `get_variable_defs` по ячейке используется как быстрая контрольная сумма: какие переменные вообще в ней задействованы и с какой прозрачностью (`"var(--texticon-disabled-alt)": "#95a0b380"`).
7. Колонка Dark: значения сравниваются с `src/theme/dark.css`. Семантический токен не может давать в тёмной теме другой цвет, чем в нашей теме. Если в Figma он отличается, это ошибка макета: она фиксируется в спеке и уходит дизайнеру, а код под неё не подгоняется.

## 3. Процесс разработки компонента

Порядок: **спека → код → сверка**. Код не пишется, пока спека не утверждена.

### Шаг 1. Спека — `docs/specs/<component>.md`

Claude собирает её из Figma по ссылкам на секции. Состав:

- **Источники:** какие страницы Figma (библиотека, спецификация, Guides, попап) использованы и какие node-id (таблица из §1 для этого компонента).
- **Карта узлов:** секции и node-id каждой ячейки (состояние × размер × тема).
- **API:** свойства библиотечного варианта (`state`, `showCaption`, …) и пропы кода, которые им соответствуют (`readOnly`, `error`, `caption`, …).
- **Таблица токенов** «состояние × элемент → токен». Например:

  | Элемент | Default                | Focus/Open          | Error               | Disabled                | Read Only               |
  | ------- | ---------------------- | ------------------- | ------------------- | ----------------------- | ----------------------- |
  | Фон     | `--bg-surface`         | `--bg-surface`      | `--bg-surface`      | `--bg-surface-disabled` | `--bg-surface-disabled` |
  | Бордер  | `--border`             | `--border-accent`   | `--border-danger`   | `--border-alt`          | `--border-alt`          |
  | Лейбл   | `--texticon-secondary` | `--texticon-accent` | `--texticon-danger` | `--texticon-disabled`   | `--texticon-secondary`  |
  | …       |                        |                     |                     |                         |                         |

- **Геометрия и анимация по размерам:** `min-height`, паддинги, gap, типографика (Default / Micro) и переходы из `Guides` (длительность, функция).
- **Поведение:** то, что в Figma видно только как разные кадры. Например, «лейбл всплывает, если есть значение, плейсхолдер или открыт попап».
- **Ошибки макета:** найденные несоответствия в Figma для дизайнера.
- **Открытые вопросы.**

После этого ты утверждаешь спеку или правишь её. Правка спеки обходится дешевле, чем цикл «а фон? а иконка?» по готовому коду.

### Шаг 2. Код и истории

- Компонент пишется строго по таблице токенов (конвенции CSS — §4).
- **State-истории повторяют сетку Showcase 1:1:** те же секции (Only Label, Label + Input, …), те же строки в том же порядке, колонки Default / Micro.
- **В сетке только статические состояния:** Default, Error, Disabled, Read Only. Focus/Open/Hover в сетку не добавляются, их Claude проверяет кликами при сверке.
- `parameters.design` ведёт на секцию Showcase.

### Шаг 3. Сверка

1. **Сверка по именам токенов.** В `get_design_context` цвета приходят как `var(--texticon-disabled-alt, …)`, и эти имена совпадают с именами в нашем CSS. Поэтому для каждой пары «состояние × элемент» достаточно сравнить имя токена из Figma с именем в `<component>.module.css`. Скрипт для этого не нужен. Цвета, которые в Figma лежат не переменной, а hex в SVG (иконки), сначала переводятся в токен (§2, п. 5), потом сравниваются по имени.
2. **Числа (геометрия, типографика).** Размеры, отступы и положение элементов сверяются со спекой разовым замером в Storybook через Playwright (`getBoundingClientRect`, `getComputedStyle`): высота, верхний и боковые отступы, положение шеврона, левый край подписи. Важная деталь: Figma отсчитывает отступы от внешнего края поля, а CSS-padding считается от внутреннего, поэтому из каждого отступа вычитается 1px обводки.
3. **Интерактив:** клики через Playwright (открытие, Error + Open, клик по лейблу, клавиатура) и проверка тех же значений в открытом состоянии.
4. **Тёмная тема:** проверяется, что в dark используются те же семантические токены. Отличия в hex по макету уходят в раздел «Ошибки макета».
5. `vp check`.
6. **Отчёт:** что совпало, что исправлено, что ушло дизайнеру. Исправляется только то, что противоречит утверждённой спеке.

### Шаг 4. Закрытие

- Спека получает отметку «сверено», с датой.
- В ответе — ссылки на превью историй (`stories-preview`).

## 4. Конвенции CSS (по опыту Select)

- **Размер:** `clsx(styles.trigger, styles[size], …)`. Класс размера задаёт геометрию корня и CSS-переменные типографики для вложенных элементов (`--select-body-font`, `--select-label-small-font`, …). Отдельных `*Micro`-классов на дочерних элементах не бывает.
- **CSS-переменные — только для того, что зависит от состояния корня и применяется во вложенном элементе** (пример — `--select-label-color`). Свойства самого корня (фон, бордер) пишутся прямо в селекторах состояний.
- **Состояния Base UI** берутся через data-атрибуты (`[data-popup-open]`, `[data-disabled]`, `[data-placeholder]`). Собственные состояния (`readOnly`, `error`) задаются классами на корне.
- **Если элемент постоянен во всех состояниях,** цвет задаётся прямо (пример: плейсхолдер всегда `--texticon-tertiary`), без переменной.
- Вложенный `:has(:has())` браузеры не поддерживают — только плоский `:has()`.
- Декоративный текст внутри кнопки-триггера получает `pointer-events: none`, иначе клик по нему не откроет попап.
- Комментарии в CSS пишутся на русском и объясняют только неочевидное.

## 6. Чек-лист перед началом нового компонента

- [ ] Известно, из каких страниц Figma собирается компонент (таблица в §1; для нового компонента — ссылки на библиотеку, `Specificaton` и `Guides`).
- [ ] Спека `docs/specs/<component>.md` собрана и утверждена.
- [ ] State-истории повторяют сетку Showcase.
- [ ] Сверка имён токенов и замеры геометрии без расхождений (или расхождения ушли дизайнеру).
- [ ] `vp check` проходит.
